# BidPulse 重构计划书

> 目标：在不改变现有业务行为的前提下，提升结构清晰度、可维护性和工程规范性。
> 原则：小步提交；每批修改后跑后端全量测试、前端单测/E2E/构建；通过后再提交推送。

## 一、优先级定义

- **P0**：结构错位或明显重复，改动小、收益高，优先处理。
- **P1**：可维护性问题，影响后续迭代速度，但不影响当前功能。
- **P2**：工程规范、测试补强、生产化能力，按时间排期。

## 五、P2：生产化

- [x] P2-1 登录 / 权限 / 审计
  - 无状态 Bearer token（HMAC-SHA256），密码只从 `BIDPULSE_*_PASSWORD` 注入；未配置时生成一次性演示密码。
  - 角色：VIEWER 只读 / OPERATOR 可写控制台 / ADMIN 额外可写 `/admin/**`、读 Actuator 与审计。
  - `/console-api/v1/audit` + `audit_log` 表记录登录、写操作与安全拒绝（401/403 的操作人、角色、路径、状态、IP）。
  - 未做：企业 SSO/MFA、审计导出/保留策略；这些依赖外部身份源与合规要求。
- [ ] P2-2 告警规则与通知。
- [ ] P2-3 故障注入 / demo 数据重置。
- [ ] P2-4 SSE / WebSocket 实时推送。
- [ ] P2-5 移动端布局与可访问性。
- [ ] P2-6 JaCoCo / Vitest coverage 门槛。

### 生产化边界（本轮仅文档化，不实现）

单实例、Kafka RF=1、Redis 无持久化是刻意保留的 demo 边界：多实例需要分布式调度，Kafka 多副本需要多 Broker，Redis 持久化会削弱冷启动重建演示。详细差异与面试口径见 `README.md` 的「生产化差异」和 `docs/architecture.md` 第 9 节。

### P2 优先级判断（结合当前单机演示形态）

| 项 | 判断 | 理由 |
|---|---|---|
| P2-1 登录 / 权限 / 审计 | **必要，已完成** | `/admin/**` 原来无鉴权；写操作和消费组暂停必须能回答“谁做的” |
| P2-2 告警通知 | 生产必要，演示非必要 | 当前有 `ReconReport` 与日志；单机演示不需要外部通知通道 |
| P2-3 故障注入 / 重置 | 演示增强，非必要 | `fallback.force` 与暂停消费已覆盖主要演示故障；完整注入需要环境隔离 |
| P2-4 SSE / WebSocket | 非必要 | 2–5s 轮询足够支撑当前页面；实时推送只有在高频演示/多用户时才值得 |
| P2-5 移动端 / a11y | 非必要（可后置） | 已有响应式断点；主要演示场景是桌面浏览器 |
| P2-6 覆盖率门槛 | 非必要（工程债） | 行为断言已覆盖关键路径；覆盖率数字容易制造虚假安全感 |

## 六、2026-11-05 生产化第一批（P0）

参考 EchoFrame 的工程防线，结合本项目现状落地。目标不是加功能，而是让「测试不污染、配置不裸奔、CI 能拦住问题」。

- [x] P0-A 测试隔离
  - 集成测试统一改用 `@BidPulseIntegrationTest`（`testsupport/`），不再手写 `@Tag("integration")`。
  - 显式开关 `BIDPULSE_IT=true` 才执行；普通 `mvn test` 由 tag 排除，`-Pfull-tests` 下缺少开关直接失败，避免静默跳过。
  - 环境变量守卫：JDBC 必须是本机 `*_it` 库、Redis database 必须是 `1..15`、Kafka 主/死信主题必须以 `bidpulse_it_` 开头。
  - 上下文启动后用实际 `DatabaseMetaData` 二次校验库名，防止连接串被覆盖。
  - `tools/init-it-db.sh` 一键初始化 `bidpulse_it`（建库 + baseline + 全部迁移）。
- [x] P0-B 迁移纪律
  - `sql/all-schema.sql` 定位为「全新库 baseline」，不再承载存量库升级说明。
  - 新增 `sql/migrations/`：`YYYYMMDD_NN_*.sql`、append-only、`information_schema` 判重、在线 DDL、写入 `schema_migration`。
  - baseline 预置 `schema_migration` 并记录已包含的版本；CI 每次重跑 baseline + 迁移，验证幂等。
- [x] P0-C CI 加固与发布门禁
  - `permissions: contents: read`、`concurrency` 取消旧构建、所有 job 设置 `timeout-minutes`。
  - 第三方 action 全部固定到 commit SHA。
  - 后端流水线：`git diff --check` → 密钥扫描 → 初始化 `bidpulse_it` → 时区校验 → `mvn -B -ntp verify -Pfull-tests` → 上传 surefire → 启动 jar 做 `/actuator/health` 冒烟。
  - 新增 `release-gate` 聚合 job，分支保护只需勾选一个 check。
- [x] P0-D 配置校验
  - `BidPulseProperties` 开启 `@Validated` + Bean Validation：金额、比例、超时、候选上限、cron、Kafka 主题名、账号角色均在启动时校验。
  - cron 用 Spring `CronExpression.parse` 校验，非法表达式直接启动失败。
- [x] P0-E 密钥卫生
  - 基础设施连接、认证密码/密钥全部改为 `${ENV:default}`，默认值只保留本地 demo。
  - `prod` profile 由 `ProductionConfigGuard` 兜底：缺 `BIDPULSE_AUTH_SECRET`、数据库密码或账号密码时拒绝启动。
  - `application-prod.yml` 只暴露 `health,info`；`.env.example` 提供模板且不含真实密钥。
  - `.gitignore` 增加 `.env*`、私钥、`application-local.yml`；CI 用 `tools/check-secrets.sh` 扫描高置信度泄露。

## 七、每批验收标准

```bash
# 后端
mvn test                     # 纯单测（95 个）
bash tools/check-secrets.sh  # 密钥扫描
tools/init-it-db.sh          # 初始化 *_it 测试库（需要 MySQL 客户端）
BIDPULSE_IT=true ... mvn test -Pfull-tests   # 全量（127 个，需要 MySQL / Redis / Kafka）

# 前端
cd console-ui
npm run lint
npm test
npm run test:e2e             # mock
E2E_BASE_URL=http://127.0.0.1:5173 E2E_USERNAME=admin E2E_PASSWORD='<密码>' npm run test:e2e  # 真实后端
npm run build
```

每批必须满足：

1. 后端全量测试通过；
2. 前端单测 + mock E2E + 真实后端 E2E 通过；
3. 构建通过；
4. 无临时调试代码、无未提交构建产物；
5. 通过后提交并推送。
