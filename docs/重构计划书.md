# BidPulse 重构计划书

> 目标：在不改变现有业务行为的前提下，提升结构清晰度、可维护性和工程规范性。
> 原则：小步提交；每批修改后跑后端全量测试、前端单测/E2E/构建；通过后再提交推送。

## 一、优先级定义

- **P0**：结构错位或明显重复，改动小、收益高，优先处理。
- **P1**：可维护性问题，影响后续迭代速度，但不影响当前功能。
- **P2**：工程规范、测试补强、生产化能力，按时间排期。

## 二、P0：结构清理

- [x] P0-1 把 `DltReplayAdminService` 从 `console/query` 移到 `console/command`
  - 它是写操作，不应与只读查询混在一起。
- [x] P0-2 合并 Kafka lag 两套逻辑
  - `ConsumerAdminController` 改为复用 `KafkaLagQueryService`，避免同一消费组两个入口结果不一致。
- [x] P0-3 去掉控制台 CORS 配置重复定义
  - 删除 `BidPulseProperties.Console.allowedOrigins` 中不再使用的字段，只保留配置项与 `@Value`。
- [x] P0-4 去掉 `sql/all-schema.sql` 固定 `CREATE DATABASE / USE bidpulse`
  - 让 schema 可以导入任意测试库，避免测试前必须 `sed`。
- [x] P0-5 增加 `.editorconfig`
  - 统一 Java/TS/Vue/SQL/Markdown 的换行、缩进、字符集。

## 六、每批验收标准

```bash
# 后端
mvn test                     # 纯单测
mvn test -Pfull-tests        # 需要 MySQL / Redis / Kafka

# 前端
cd console-ui
npm test
npm run test:e2e             # mock
E2E_BASE_URL=http://127.0.0.1:5173 npm run test:e2e  # 真实后端
npm run build
```

每批必须满足：

1. 后端全量测试通过；
2. 前端单测 + mock E2E + 真实后端 E2E 通过；
3. 构建通过；
4. 无临时调试代码、无未提交构建产物；
5. 通过后提交并推送。
